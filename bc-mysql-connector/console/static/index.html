Demonstration

run top to bottom

1Pull everything from Business Central

Reads every customer, vendor, item and sales order, page by page, into the MySQL mirror tables.

2A user edits a record in Business Central

Simulates someone changing a value inside BC. Only that record is pulled on the next sync.

3Change a value from MySQL

Your systems write to bc_outbox; the connector sends it to BC with an ETag check.

4Create a customer from MySQL

BC assigns the customer number; it comes back into MySQL with the new record.

5Both sides edit the same record

BC changes the city while MySQL changes the credit limit. The connector detects the stale ETag (HTTP 412), re-reads and keeps both changes.

6Business Central is busy

BC limits request rates. With throttling on, every third call gets HTTP 429 and the connector waits and retries.
